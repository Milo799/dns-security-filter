# Windows DNS 安全过滤中间件 需求说明书（精简版 V3.1）

## 一、建设目标

在不改动、不替换企业现有 **Windows Server 原生 DNS 服务**的前提下，对外网域名解析增加安全过滤能力：

- 外网域名请求经 **DNS 代理中间件** 转发至 **DNS 安全过滤平台**，平台完成黑白名单与威胁情报检测；
- 命中风险的请求统一返回告警 IP（可配置），正常请求照常解析；
- **完整记录所有被过滤（拦截/剔除）的内容**，支持查询与追溯；
- 对原有 Windows DNS 架构**最小改动、最小侵入**，内网解析与 AD 域能力零影响。

## 二、整体架构

### 1. 组件与角色

| 组件 | 部署位置 | 职责 |
|------|----------|------|
| Windows DNS | 既有（可多台） | 内网解析照常；仅新增一条转发器配置，将外网域名请求转发至代理中间件 |
| DNS 代理中间件 | **独立部署**（与 Windows DNS 不同机，可多个） | 接收 Windows DNS 转发的外网请求 → 透传至安全过滤平台 → 回传结果 |
| DNS 安全过滤平台 | 独立服务器（单实例） | 黑白名单 + 威胁情报检测、拦截应答、被过滤内容记录、Web 管理 |

### 2. 请求链路

```
内网终端
   │  DNS 查询
   ▼
Windows DNS
   ├─ 内网域名 ──▶ 本地权威解析，直接返回（不经代理、不经平台、不记录）
   └─ 外网域名 ──▶ 转发器
                        ▼
              DNS 代理中间件（独立部署）
                        │ 透传
                        ▼
              DNS 安全过滤平台
                        ├─ 域名前置检测（本地黑名单 + 威胁情报 API）
                        │     ├─ 命中恶意 → 返回告警 IP（记录被过滤内容）
                        │     └─ 无风险 → 请求公网 DNS 解析
                        ├─ IP 后置过滤（解析出 IP 后）
                        │     ├─ 全部恶意 → 返回告警 IP（记录）
                        │     ├─ 部分恶意 → 剔除恶意 IP、保留正常 IP（记录）
                        │     └─ 全部正常 → 原样返回
                        └─ 返回结果
                        ▼
        经代理中间件回传 → Windows DNS → 内网终端
```

### 3. 代理中间件部署说明

- **独立部署（默认，推荐）**：代理中间件安装在独立机器上（可与安全过滤平台同机，或另设一台）；**Windows DNS 服务器上不安装任何程序**，仅将转发器指向代理 IP，对原有 Windows DNS 改动最小；
- 同机部署（代理与 Windows DNS 同机，走回环地址）仅在临时测试等特殊场景使用，不作为生产推荐；
- 支持多台 Windows DNS 分别对接各自的代理中间件，或多个代理共同对接同一安全平台；
- 代理仅做请求转发与结果回传，不含任何安全判断逻辑，性能损耗可忽略。

## 三、安全过滤平台核心功能

### 1. 双维度检测

- **域名前置检测**（转发公网 DNS 之前）：校验本地域名黑名单（支持 `*.xxx.com` 通配符）+ 多个开源免费威胁情报 API 并行检测；命中恶意域名直接拦截，返回固定告警 IP，终止解析；
- **IP 后置过滤**（公网解析出 IP 之后）：校验本地 IP 黑名单 + 威胁情报 API；命中恶意则剔除该 IP、保留其余正常 IP，全部恶意则返回告警 IP。

### 2. 黑白名单管理

- 支持域名/IP 黑名单与白名单；白名单条目跳过全部检测、直接放行；
- 支持通配符匹配；可通过 Web 界面增删改、批量导入/导出、启用/禁用，并可填写备注；
- 名单持久化存储，服务重启不丢失；变更留痕（操作人、时间、内容）。

### 3. 威胁情报 API 配置

- 支持对接多个免费威胁情报 API，可独立启用/禁用，支持并行调用与超时控制；
- **API 全部超时/故障时默认拦截**，不自动放行；仅管理员手动临时关闭检测方可放行，操作留痕。

### 4. 拦截应答

- 命中风险统一返回**可配置的固定告警 IP**（不返回 NXDOMAIN、不丢弃报文）；
- 正常请求原样返回公网解析结果，不做任何篡改。

### 5. 被过滤内容记录（核心功能）

- **必录**：所有被拦截/剔除的请求，记录字段包括——时间、请求域名、解析类型、过滤原因（命中黑名单 / 命中哪个 API）、处理动作（拦截 / 剔除）、恶意 IP 明细、最终返回结果；
- 支持按时间、域名、过滤原因等条件查询，支持导出；
- 放行记录可选择性开启，默认关闭、按需启用；
- 日志自动轮转与清理，保留周期可配置。

### 6. 简单管理

- Web 管理界面：黑白名单管理、日志查询、检测开关（一键启停安全检测）、平台运行状态展示；
- 管理员账号密码登录，禁止匿名访问。

## 四、故障处理

| 故障场景 | 处理方式 |
|----------|----------|
| 单个/全部威胁情报 API 故障 | 平台默认拦截外网请求，不自动放行；管理员可在平台临时关闭检测放行（操作留痕） |
| 安全过滤平台故障/不可用 | 在 Windows DNS 上**修改转发器地址**，改回原公网 DNS（或原备份配置），外网解析暂时绕过过滤；平台恢复后改回指向代理中间件 |
| 代理中间件故障 | 同上，Windows DNS 转发器改回公网 DNS 即可 |

- 故障期间外网解析无过滤、无记录，需人工关注并尽快恢复；
- 建议备份原有转发器配置，便于快速切换与回退。

## 五、对原有架构的影响（最小侵入）

- Windows DNS 仅新增一项**转发器配置**（指向代理中间件），其余全部保留；
- 内网权威解析、AD 集成 DNS、SRV 记录、反向解析等完全不变，不经代理与平台；
- 内网终端零改动、无感知上线；
- 回退方式简单：恢复原转发器配置即可，无残留影响。

## 六、部署建议

- 安全过滤平台：独立服务器，与各代理中间件网络互通（纯 IPv4 环境）；
- 代理中间件：独立部署（与 Windows DNS 不同机），确保 Windows DNS 服务器不安装任何第三方程序；代理可与安全过滤平台同机或另设一台；
- 资源参考：平台 4 核 4G 起、日志磁盘 50GB 起；代理中间件资源占用极低（1 核 1G 即可），按实际解析量评估。

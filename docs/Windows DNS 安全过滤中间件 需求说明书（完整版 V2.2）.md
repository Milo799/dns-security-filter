# Windows DNS 安全过滤中间件 需求说明书（完整版 V2.2）

> 本文档由《需求说明书-v1》（精简版 V3.1）合并开发至今（V1.1~V2.2）用户提出的全部需求与优化项而成，
> 是系统当前能力的完整需求基线。正文保持 V3.1 的精简骨架，各章节补充迭代增强内容；V2.1 之后新增内容以「★」标注。

## 一、建设目标

在不改动、不替换企业现有 **Windows Server 原生 DNS 服务**的前提下，对外网域名解析增加安全过滤能力：

- 外网域名请求经 **DNS 代理中间件** 转发至 **DNS 安全过滤平台**，平台完成黑白名单与威胁情报检测；
- 命中风险的请求统一返回告警 IP（可配置），正常请求照常解析；
- **完整记录所有被过滤（拦截/剔除）的内容**，支持查询与追溯；
- 对原有 Windows DNS 架构**最小改动、最小侵入**，内网解析与 AD 域能力零影响。

▲ 迭代补充的建设原则：

- **检测覆盖完整**：A/AAAA 解析与 PTR 反向解析均纳入检测，不留绕过面；
- **情报源分层**：本地离线大名单（零依赖、零延迟）与在线威胁情报 API（实时、厂商级）分层叠加，
  高及时哨兵（URLhaus 30 分钟）与大名单（每日）按各自周期自动更新；
- **部署可移植**：Linux systemd 与 Docker 两种部署方式，一套镜像随处运行；
- ★ **10 万终端规模化**：检测缓存分层（域名/IP 双结论缓存）、DNSBL 默认启用、日志异步削峰、限流熔断，放行路径毫秒级（详见第七章迭代 19~21 与第九章）。

## 二、整体架构

### 1. 组件与角色

| 组件 | 部署位置 | 职责 |
|------|----------|------|
| Windows DNS | 既有（可多台） | 内网解析照常；仅新增一条转发器配置，将外网域名请求转发至代理中间件 |
| DNS 代理中间件 | **独立部署**（与 Windows DNS 不同机，可多个） | 接收 Windows DNS 转发的外网请求 → 透传至安全过滤平台 → 回传结果（纯转发，无安全逻辑） |
| DNS 安全过滤平台 | 独立服务器（单实例） | 黑白名单 + 离线大名单 + 在线威胁情报检测、拦截应答、被过滤内容记录、Web 管理 |

▲ 平台内部检测链路（优先级从高到低）：

```
检测入口（A / AAAA / PTR 均走完整链路）
   ├─ ① 手工白名单（域名/IP/CIDR，命中直接放行，跳过一切检测）
   ├─ ② 手工黑名单（域名通配符/IP/CIDR）
   ├─ ③ 离线大名单（threat_list：hagezi / StevenBlack / URLhaus / OISD 本地匹配）
   ├─ ④ 在线威胁情报源（并行查询，多源融合裁决）
   └─ ⑤ 公网解析后的 IP 后置过滤（逐 IP 校验上述名单与情报源）
```

### 2. 请求链路

```
内网终端
   │  DNS 查询
   ▼
Windows DNS
   ├─ 内网域名 ──▶ 本地权威解析，直接返回（不经代理、不经平台、不记录）
   └─ 外网域名 ──▶ 转发器
                        ▼
              DNS 代理中间件（独立部署）
                        │ 透传（含 EDNS0 Client Subnet，原样不剥离）
                        ▼
              DNS 安全过滤平台
                        ├─ 域名前置检测（本地黑名单 + 离线大名单 + 在线情报源）
                        │     ├─ 命中恶意 → 返回告警 IP（记录被过滤内容）
                        │     └─ 无风险 → 请求公网 DNS 解析
                        ├─ IP 后置过滤（解析出 IP 后）
                        │     ├─ 全部恶意 → 返回告警 IP（记录）
                        │     ├─ 部分恶意 → 剔除恶意 IP、保留正常 IP（记录）
                        │     └─ 全部正常 → 原样返回
                        └─ 返回结果
                        ▼
        经代理中间件回传 → Windows DNS → 内网终端
```

### 3. 代理中间件部署说明

- **独立部署（默认，推荐）**：代理中间件安装在独立机器上（可与安全过滤平台同机，或另设一台）；**Windows DNS 服务器上不安装任何程序**，仅将转发器指向代理 IP，对原有 Windows DNS 改动最小；
- 同机部署（代理与 Windows DNS 同机，走回环地址）仅在临时测试等特殊场景使用，不作为生产推荐；
- 支持多台 Windows DNS 分别对接各自的代理中间件，或多个代理共同对接同一安全平台；
- 代理仅做请求转发与结果回传，不含任何安全判断逻辑，性能损耗可忽略；
- ★ **双机生产拓扑**（10 万终端推荐）：机 A 代理（Go 二进制，1 核 1G 起）+ 机 B 平台（4 核 4G 起），一键脚本 `deploy/install-proxy.sh` / `install-platform.sh` 分别落位（幂等可重跑、配置已存在永不覆盖）；部署方案详见 `docs/生产环境部署方案（Linux 双机）.md`。

▲ 迭代补充：

- **EDNS0 Client Subnet（RFC 7871）透传**：Windows DNS 转发时附加客户端子网，代理原样透传（含 OPT RR 不剥离），平台解析提取并记入过滤日志 `client_ip` 字段；不支持 ECS 的旧客户端该字段记空；
- 代理与平台间为**标准 DNS 协议**（UDP/TCP 53），无私有协议，便于排障与替换。

## 三、安全过滤平台核心功能

### 1. 双维度检测（▲ 扩展为"三类型全量检测"）

- **域名前置检测**（转发公网 DNS 之前）：校验本地域名黑名单（支持 `*.xxx.com` 通配符）+ 离线大名单 + 在线威胁情报 API 并行检测；命中恶意域名直接拦截，返回固定告警 IP，终止解析；
- **IP 后置过滤**（公网解析出 IP 之后）：校验本地 IP 黑名单 + 离线大名单 + 在线威胁情报源；命中恶意则剔除该 IP、保留其余正常 IP，全部恶意则返回告警 IP；
- ▲ **PTR 反向解析过滤**：PTR(12) 类型查询同样走完整检测链路——解析出目标 IP 后按 IP 维度校验白名单（放行）、黑名单/离线大名单/在线情报源（拦截）；非标准 PTR 查询名直接转发不误拦；
- ▲ **AAAA 同等过滤**：A 与 AAAA 记录均走完整检测流程；AAAA 命中恶意返回**空应答（RCODE=NOERROR）**；其他 QTYPE 直接转发；
- ▲ **三态语义（威胁情报查询结果）**：命中 → 拦截；明确未命中 → 放行；网络失败/超时 → **无结论**，参与 fail-safe 默认拦截；
- ★ **检测结论缓存分层**：域名结论缓存（domain_cache，TTL 300s/容量 100 万，LRU）与 IP 结论缓存（ip_cache，TTL 900s/容量 20 万）——同域名/同 IP 重复查询跳过在线情报源实查；**fail-safe 无结论不写缓存**（瞬时故障不会固化为持续误拦）；情报源启停/融合策略/名单变更联动清空对应缓存；
- ★ **IP 后置过滤并行化**：先查本地黑名单与离线大名单（内存 O(1)），剩余未命中 IP 线程池并行查询在线源（单 IP 直查免线程开销）；
- ★ **单次上游往返**：放行路径一次公网解析取原始应答，从应答提取 IP 做后置过滤，全部正常时**直接返回上游原始应答**（完整保真上游 TTL/EDNS0），不再二次解析。

### 2. 黑白名单管理

- 支持域名/IP 黑名单与白名单；白名单条目跳过全部检测、直接放行（最高优先级）；
- 支持通配符匹配（域名）、CIDR（IP）；可通过 Web 界面增删改、批量导入/导出、启用/禁用，并可填写备注；
- Web 界面为**单一"人工情报源"页面内白/黑双 Tab** ★（V1.x 拆分两页 → 迭代 17 合并），各自独立工具栏/筛选/表格防操作错误；术语全局统一"人工白名单/人工黑名单"；
- ★ CSV 批量导入自动消重：同名单内 (list_type,target,value) 重复自动去重（域名键不区分大小写），返回已入库/文件内重复/库内重复明细；跨名单同值不拦截但返回冲突明细警示（白名单命中优先放行）；
- 名单持久化存储，服务重启不丢失；变更留痕（操作人、时间、内容），支持审计详情可读化展示。

### 3. 离线大名单 ▲（本地导入离线匹配）

- 内置来源（可独立启用/停用/导入更新/清空，自定义 URL 导入任意 plain/hosts/adblock 格式）：

| 来源 | 内容 | 规模 | 自动更新周期 | 定位 |
|------|------|------|-------------|------|
| hagezi 威胁情报（hagezi_ti） | 恶意软件/钓鱼/C2/欺诈（TIF 完整版） | 约 210 万条 | 每日 | 安全专项主名单，量最大、误伤最小 |
| hagezi 威胁情报精简（hagezi_mini）▲ | 同上（TIF Mini 精简版） | 约 17 万条 | 每日 | 内存占用约为完整版 1/12，资源受限部署选择 |
| hagezi 综合大名单（hagezi_ult） | 恶意+广告+追踪（ULTIMATE） | 约 27 万条 | 每日 | 全量拦截，误伤面较大 |
| StevenBlack hosts | 广告/恶意/追踪统一 hosts | 约 15 万条 | 每日 | 经典通用名单 |
| URLhaus 恶意域名 | 当前活跃恶意软件分发域名 | 约 300~2000 条 | **30 分钟** | 高及时哨兵名单，0day 响应 |
| OISD 综合大名单 | 恶意/广告/追踪（Big） | 约 20 万条 | 每日 | 低误报，与 hagezi 互为独立交叉验证 |

- **导入机制**：整源替换（重复导入即增量更新，不留陈旧条目）；导入在后台执行并实时展示进度（下载→解析→入库三阶段）；▲ 支持多源并发导入，进度轮询按源独立进行，刷新页面可恢复进行中任务的进度；
- **匹配机制**：内存缓存 O(1) 匹配——域名精确匹配 + 逐级父域后缀匹配（列表含 bad.com 则 a.bad.com 命中）、IP 精确匹配；导入/启停/清空后自动刷新缓存；
- **下载容错**▲：GitHub raw 主地址不可达或中段静默丢弃时，自动降级到 jsDelivr CDN 镜像（hagezi / oisd / StevenBlack 已配置镜像规则）；流式下载超时拆分（连接 15 秒 / 读空闲 30 秒），卡死快速触发降级；降级前重置进度字节，避免进度条回跳；
- **按源周期自动更新**▲：每个内置源带独立更新周期（`update_interval_s`），到期才更新、未到期跳过；调度 tick = min(用户配置间隔, 各源最小周期)（下限 60 秒），保证 URLhaus 的 30 分钟短周期能被及时调度；单源失败不影响其他源与服务；**各源实际更新周期 = min(源内置周期, 用户全局配置间隔)**——用户把全局间隔调短（如 1 小时），hagezi 等长周期源随之缩短提前到期，urlhaus 等源自身更短的不受影响；
- **查询性能**▲：统计覆盖索引（source, updated_at, enabled）+ 进程内统计缓存（写操作联动失效）+ 服务启动后台预热线程（内存匹配缓存与统计缓存双预热），源列表页毫秒级响应，服务重启后无首次查询阻塞；
- **优先级**：离线大名单命中判定在手工黑名单之后、在线情报源之前；白名单始终最高优先级；
- 提供"查看条目"分页弹窗，可按关键字/启停状态检索来源内条目。

### 4. 威胁情报 API 配置（▲ 扩展为"内置多源 + 可扩展"）

- 支持对接多个免费威胁情报 API，可独立启用/禁用，支持并行调用与超时控制；
- **内置源清单**（seed 预置、开箱即用，免 Key 源直接可用；▲ URLhaus 官方已从免 Key 改为强制鉴权）：

| 类别 | 来源 | 类型 | 需 Key | 说明 |
|------|------|------|--------|------|
| DNSBL | spamhaus_zen / spamhaus_dbl | IP / 域名 | 否 | 全球最大反垃圾/恶意源（SBL/XBL/PBL） |
| DNSBL | dronebl | IP | 否 | 僵尸网络/扫描源 |
| DNSBL | spfbl | 域名+IP | 否 | 反垃圾/恶意源 |
| 免费 API | URLhaus | 域名+IP | 是（Auth-Key）▲ | abuse.ch 活跃恶意分发（在线查询版）；官方已强制 HTTP 头 Auth-Key，auth.abuse.ch 免费申请；未配 Key 时测试连通性给出明确提示 |
| 免 Key API | PhishTank | 域名 | 否 | 钓鱼站点众包库 |
| 免 Key API | DShield | IP | 否 | SANS 攻击源情报（可配 min_count/max_age） |
| 免 Key API | Blocklist.de | IP | 否 | 暴力破解/扫描攻击源 |
| 厂商 API | ThreatFox | 域名+IP | 是 | abuse.ch C2 专项库 |
| 厂商 API | 微步威胁情报 | 域名+IP | 是 | 国内厂商，个人免费额度约 50 次/天 |
| 厂商 API | IBM X-Force | 域名+IP | 是 | 评分制，非商业免费 Key |
| 厂商 API | AlienVault OTX | 域名+IP | 是 | 恶意域名/IP 量大 |
| 厂商 API | GreyNoise | IP | 是 | 扫描器识别，专治误拦扫描 IP |

> 说明：360 威胁情报免费版仅 20 条/天且需商务申请（接口不公开），未内置，后续可按需接入。

- **三态语义**：命中→拦截；明确未命中→放行；网络失败/超时→无结论（fail-safe 默认拦截）；
- ★ **出厂默认仅启用 DNSBL 四源**（spamhaus_zen / spamhaus_dbl / dronebl / spfbl）——DNS 协议查询亚毫秒、无 HTTP 配额限制，适合 10 万终端实时检测链路；HTTP 类免费/厂商源默认停用，仅测试中心人工核验时按需启用（对齐部署方案 3.1-A 策略）；存量部署不覆盖管理员已有配置；
- ★ **单源限流熔断**：适配器连续失败自动熔断（半开试探恢复），熔断期间该源返回无结论不阻塞检测；降级开关可整体跳过在线情报查询（性能兜底）；
- **能力声明**：每个适配器声明支持域名/IP 维度，检测时按能力分配查询，避免"仅 IP 类源参与域名查询"导致误判；
- ▲ **诊断信息**：在线源"测试连通性"失败时返回具体原因（缺 Key / Key 无效 / 请求过于频繁 / 网络错误），适配器维护 last_error 供排查；在线源支持**编辑**（超时、描述、API Key 等，Key 留空表示保持不变），适配器类型创建后不可改；
- 未配置 Key 的 Key 型源不发起请求、直接返回无结论，不影响 fail-safe 裁决。

### 5. 多源融合策略 ▲

- 融合策略三选一（Web 界面切换，变更记入审计）：

| 策略 | 规则 | 适用 |
|------|------|------|
| any（默认，推荐） | 任一启用源判定恶意即拦截 | 安全优先 |
| majority | 多数启用源判定恶意才拦截 | 平衡 |
| all | 全部启用源一致判定恶意才拦截 | 最保守、最少误拦 |

- **fail-safe**：全部启用源均超时/异常（无结论）时按安全优先默认拦截，不自动放行；
- 仅管理员手动临时关闭检测方可放行，操作留痕。

### 6. 测试中心 ▲（人工验证）

- Web 新增"测试中心"页面，支持输入域名或 IP（含 PTR 模式）进行**只读探测**（不写日志、不影响运行）：
  - 手工白名单/黑名单命中规则逐条展示；
  - 离线大名单命中展示（来源+条目）；
  - 在线情报源逐源查询结果（hit/miss/error）表格；
  - 公网解析结果 + IP 后置逐 IP 校验 + 最终裁决横幅（拦截/放行/剔除）。

### 7. 拦截应答

- 命中风险统一返回**可配置的固定告警 IP**（不返回 NXDOMAIN、不丢弃报文）；AAAA 命中返回空应答（NOERROR）；
- 告警应答 TTL 可配置；正常请求原样返回公网解析结果，不做任何篡改。

### 8. 被过滤内容记录（核心功能）

- **必录**：所有被拦截/剔除的请求，记录字段包括——时间、**客户端 IP（EDNS0 Client Subnet）**、请求域名、解析类型、过滤原因（命中黑白名单 / 离线大名单来源 / 命中哪个在线情报源）、处理动作（拦截 / 剔除）、**恶意 IP 明细**、**最终返回结果**、**命中情报源列表**；
- 支持按时间、域名、过滤原因、客户端 IP 等条件查询，支持导出（CSV）；
- 放行记录可选择性开启，默认关闭、按需启用（开启后日志量显著增大）；
- ★ **放行日志采样**：`allow_log_sample_rate`（0~100%，默认 100% 即全采）——计数取模确定性采样，10 万终端高流量场景可降至 1%~10% 控制日志量，被拦截/剔除日志始终全量记录不受采样影响；
- ★ **写入削峰（异步批量）**：过滤日志经内存队列异步批量写入 SQLite（队列上限保护内存）；观测接口 `GET /api/log-writer/stats` 返回队列长度/累计写入/丢弃数——`dropped>0` 表示写入跟不上需调大保留周期或降低采样率；
- 日志自动轮转与清理，保留周期可配置。

### 9. 简单管理

- Web 管理界面：**人工情报源（白/黑双 Tab）**、威胁情报源管理（在线源表格 + 离线大名单表格 + 在线源编辑）、日志查询、测试中心、检测开关（一键启停安全检测）、平台运行状态展示、操作审计；
- ▲ 操作审计：敏感操作（名单增删改、情报源启停/导入、融合策略切换、检测开关、系统配置修改等）全部留痕，审计详情可读化展示；
- ▲ 系统配置热生效：Web 修改配置（告警 IP/TTL、上游 DNS、日志保留、检测开关、自动更新等）即时生效，无需重启服务；★ 双进程部署（systemd 三服务/Docker 双容器）下，DNS 进程经 **cross_sync 60 秒轮询**感知 Web 进程的配置/名单/情报源变更并联动失效缓存，最长 60 秒生效；
- ★ **SOC 安全态势仪表盘**：三段式大屏——①威胁总览大数字带（今日拦截/放行/拦截率等 countUp 动效 + 风险等级仪表）②分析维度（近 24h 拦截趋势柱线混合图、来源构成环形图 + Top 恶意域名、五层检测链路状态、情报源健康面板）③实时事件流（新拦截事件 3 秒轮询滚动 + 客户端 Top + 24 小时热力图）；主数据 10 秒自动刷新；
- ★ **导航信息架构**：总览（安全态势）/ 监控（过滤日志）/ 策略管理（融合策略 + 测试中心）/ 威胁情报（在线情报源 + 离线情报源 + 人工情报源）/ 系统（系统配置 + 操作审计）；
- 管理员账号密码登录（JWT），禁止匿名访问；初始密码首次初始化后必须修改。

## 四、故障处理

| 故障场景 | 处理方式 |
|----------|----------|
| 单个威胁情报源故障 | 该源返回无结论，其余源继续裁决；全部源无结论时 fail-safe 默认拦截 |
| 全部在线情报源故障 | 平台默认拦截外网请求，不自动放行；管理员可在平台临时关闭检测放行（操作留痕） |
| 离线大名单更新失败 | 单源失败隔离，保留现有数据继续匹配，不影响其他源与服务 |
| 安全过滤平台故障/不可用 | 在 Windows DNS 上**修改转发器地址**，改回原公网 DNS（或原备份配置），外网解析暂时绕过过滤；平台恢复后改回指向代理中间件 |
| 代理中间件故障 | 同上，Windows DNS 转发器改回公网 DNS 即可 |

- 故障期间外网解析无过滤、无记录，需人工关注并尽快恢复；
- 建议备份原有转发器配置，便于快速切换与回退。

## 五、对原有架构的影响（最小侵入）

- Windows DNS 仅新增一项**转发器配置**（指向代理中间件），其余全部保留；
- 内网权威解析、AD 集成 DNS、SRV 记录、反向解析等完全不变，不经代理与平台；
- 内网终端零改动、无感知上线；
- 回退方式简单：恢复原转发器配置即可，无残留影响。

## 六、部署建议（▲ 扩展：systemd 原生 + Docker）

- 安全过滤平台：独立服务器，与各代理中间件网络互通（纯 IPv4 环境）；
- 代理中间件：独立部署（与 Windows DNS 不同机），确保 Windows DNS 服务器不安装任何第三方程序；代理可与安全过滤平台同机或另设一台；
- 资源参考：平台 4 核 4G 起（启用 hagezi 完整版大名单时内存占用较高，可改选 mini 精简版）、日志磁盘 50GB 起；代理中间件资源占用极低（1 核 1G 即可），按实际解析量评估；
- 平台组件：Python + FastAPI + dnslib + SQLite（单文件库，无外部数据库依赖）；代理组件：Go + miekg/dns（纯静态二进制）。

### 部署方式一：Linux systemd（原生）

- `deploy/install.sh` 一键落位：安装目录 /opt/dns-security-filter，独立运行用户 dnsfilter；
- 三个 systemd 服务：`proxy.service`（代理）、`platform-dns.service`（平台 DNS 53）、`platform-web.service`（平台 Web 8080）；
- 防火墙放行：53/UDP+TCP（平台与代理）、8080/TCP（Web，建议仅内网）。

### 部署方式二：Docker（推荐）▲

- `deploy/docker/` 提供：`Dockerfile.platform`（平台镜像：DNS + Web 双进程）、`Dockerfile.proxy`（代理镜像：Go 多阶段构建 → alpine）、`docker-compose.yml`（一键编排）；
- 配置与数据 volume 挂载（platform.yaml / config.yaml / data），改配置无需重建镜像；
- 一键启动：

```bash
docker compose -f deploy/docker/docker-compose.yml up -d --build
```

- 容器健康检查 + `restart: unless-stopped` 自动拉起；平台容器内任一进程异常退出即重启。

### 需要开通的网络地址（防火墙/安全组出站白名单）▲

入站：53/UDP+TCP、8080/TCP（Web，建议仅内网）。

出站分四类（未启用对应功能源时可不开通对应项）：

| 类别 | 地址 | 用途 |
|------|------|------|
| 构建期 | `docker.io` / `registry-1.docker.io`（或内网镜像仓库）、`pypi.org`（或国内镜像）、`proxy.golang.org`（或 goproxy.cn） | 拉取基础镜像 / Python 依赖 / Go module |
| 离线大名单 | `raw.githubusercontent.com`、`cdn.jsdelivr.net`、`urlhaus.abuse.ch` | hagezi/StevenBlack/OISD 主地址+镜像、URLhaus 名单 |
| 在线情报源 | `zen.spamhaus.org`、`dbl.spamhaus.org`、`dnsbl.dronebl.org`、`dnsbl.spfbl.net`（53/UDP）；`urlhaus-api.abuse.ch`、`threatfox-api.abuse.ch`、`api.threatbook.cn`、`api.xforce.ibmcloud.com`、`otx.alienvault.com`、`api.greynoise.io`、`checkurl.phishtank.com`、`isc.sans.edu`、`api.blocklist.de`（443/TCP） | DNSBL 查询 / 厂商威胁情报 API |
| 上游递归 DNS | `8.8.8.8`、`8.8.4.4` 或 `114.114.114.114`（UDP/TCP 53） | 平台公网域名解析 |

> 最小出站建议：`raw.githubusercontent.com`、`cdn.jsdelivr.net`、`urlhaus.abuse.ch`、上游 DNS 53。
> 完整清单详见 `deploy/docker/README.md`。
